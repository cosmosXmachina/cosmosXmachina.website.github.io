Implementation State Hidden From The Public Interface
------------------------------------------------------

The following engineering work exists behind the visible Round 1 interfaces
and is important to preserve when continuing:

- `api/ai/` contains the provider catalogue, task schemas, gateway, and wire
  adapters for OpenAI, Google Gemini, Anthropic Claude, xAI Grok, and
  OpenRouter.
- The provider selector is saved in sessionStorage and sent to the private Node
  gateway. The public provider catalogue exposes model labels and readiness but
  never credentials.
- `AI_MODE=fixture` is the required current mode. In this mode every provider
  selection uses FixtureAIProvider, trace data records the simulated target,
  and no provider network transport is called.
- Live adapters build provider-specific requests and normalize responses. They
  have only been tested with mocked transports. They have not been tested with
  real credentials, real billing, current provider model availability, or real
  provider responses, and live mode must not be enabled as part of Round 1.
- AI task schemas and business workflow rules remain outside adapters. Current
  live response parsing proves that a JSON object was returned, but complete
  runtime JSON-schema validation of live output is still a future hardening
  item.
- The Node router keeps document and order workflow state per entity, enforces
  valid transitions and shipping roles, dispatches deterministic AI-like tasks
  through AIGateway, and keeps ordinary state changes in rule code.
- The private Python service prepares deterministic document extraction and
  permission-filtered knowledge evidence before the Node AI boundary. Node has
  a fixture fallback if Python is unavailable so the public demo remains
  explorable, but production topology still requires both services.
- The browser has a deterministic fallback for static visual exploration. It
  is not a replacement for the production Node endpoint, session controls, SMTP,
  or Python pipelines.
- KPI calculations are isolated in `kpi-engine.js` and executed through a Web
  Worker. ECharts is the reason the KPI bundle is materially larger than the
  other demos; the build budget currently accepts it.
